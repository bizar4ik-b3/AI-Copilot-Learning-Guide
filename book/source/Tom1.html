Розділ 1. Що таке AI-асистент і LLM

1.1. Коротко про суть

LLM (Large Language Model, велика мовна модель) — нейромережа, навчена на величезних обсягах тексту і коду. Її базова задача: передбачити наступний фрагмент тексту (токен) з огляду на попередній. Звідси здатність писати код, пояснювати, перекладати, підсумовувати.

AI-асистент — програма-обгортка навколо LLM: вікно чату, інтеграція в IDE, доступ до ваших файлів, інструменти (термінал, пошук, запуск тестів). GitHub Copilot, ChatGPT, Claude Code — це асистенти, а GPT, Claude, Gemini — моделі всередині.

РівеньЩо цеПриклад
Модель«Мозок», що генерує текстGPT-5, Claude Sonnet, Gemini
Асистент / продуктІнтерфейс + інструменти + налаштуванняGitHub Copilot, ChatGPT, Cursor
Ваші налаштуванняІнструкції, skills, MCP для вашого проєктуcopilot-instructions.md

1.2. Як це працює (спрощено)

  1. Ваш текст розбивається на токени (шматки слів).
  2. Модель на основі токенів обчислює ймовірності наступного токена і вибирає один.
  3. Процес повторюється, поки відповідь не завершена.

Важливо: модель не «знає» факти, як база даних. Вона відтворює правдоподібні патерни. Тому вона може упевнено помилятися — це називають галюцинацією.

1.3. Три покоління роботи з AI

РежимОписПриклад у .NET

1.4. Що AI робить добре, а що погано

ДобреПогано / ризиковано

Розділ 2. Словник: терміни, які потрібно знати

Це найважливіший розділ-довідник. Повернутися до нього можна в будь-який момент; повний глосарій буде в додатках.

2.1. Базові поняття моделі

ТермінПояснення
ТокенОдиниця тексту для моделі (≈ 3–4 англ. символи; українська й код «дорожчі» — більше токенів). Ціна й ліміти рахуються в токенах.
Контекстне вікно (context window)Максимум токенів, які модель «бачить» за раз: ваш запит + історія + файли + відповідь. Вийшло за межу — старе забувається або обрізається.
Промпт (prompt)Вхідний текст-запит до моделі.
Системний промпт (system prompt)Приховані/базові інструкції, що задають роль і правила моделі («Ти асистент-програміст…»). Файли інструкцій розширюють саме цей рівень.
Completion / відповідьТе, що згенерувала модель.
Temperature«Креативність»: 0 — передбачувано й стабільно, вище — різноманітніше. Для коду зазвичай низька.
Top-p / top-kІнші способи обмежити вибір наступного токена.
Max tokensЛіміт довжини відповіді.
ГалюцинаціяПравдоподібна, але хибна відповідь (вигаданий метод List.RemoveDuplicates()).
Knowledge cutoffДата, до якої модель мала навчальні дані. Нові версії .NET можуть бути їй невідомі.
МультимодальністьМодель працює не лише з текстом, а й із зображеннями (скріншот UI → код).
Reasoning / «thinking» модельМодель, що «міркує» перед відповіддю: повільніша й дорожча, але краща для складних задач.
Fine-tuningДонавчання моделі на своїх даних. Для звичайного розробника зазвичай не потрібне.
EmbeddingЧисловий вектор, що представляє зміст тексту; основа семантичного пошуку.

2.2. Терміни роботи з контекстом і знаннями

ТермінПояснення
Контекст (context)Усе, що ви надали моделі: файли, виділений код, історія чату, інструкції.
Grounding«Заземлення» відповіді на реальних даних (ваш код, документація), щоб зменшити вигадки.
RAG (Retrieval-Augmented Generation)Спершу знайти релевантні фрагменти (пошук по embeddings), потім додати їх у промпт.
Vector databaseСховище embeddings для семантичного пошуку.
ChunkingРозбиття великих документів на шматки для індексації.
Compaction / summarizationСтиснення довгої історії в короткий підсумок, коли контекст майже заповнений.

2.3. Терміни промптингу

ТермінПояснення
Zero-shotЗапит без прикладів.
Few-shotЗапит з 1–3 прикладами очікуваного формату.
Chain-of-thoughtПрохання міркувати крок за кроком.
Role prompting«Ти — досвідчений .NET-архітектор…»
Structured outputВідповідь у суворому форматі (JSON за схемою).
Prompt injectionАтака: шкідливий текст у даних (файл, веб-сторінка) намагається «перепрограмувати» модель. Дуже важливо для агентів.

2.4. Терміни агентів і екосистеми (огляд — детально в розділах 7–12)

ТермінПояснення
Agent (агент)LLM, що в циклі «думає → викликає інструмент → дивиться результат → продовжує», доки задача не виконана.
Tool / function callingМеханізм, у якому модель просить виконати функцію (прочитати файл, dotnet test), а програма виконує й повертає результат.
MCP (Model Context Protocol)Відкритий стандарт підключення зовнішніх інструментів і даних (GitHub, БД, браузер) до будь-якого AI-клієнта. «USB-C для AI».
Custom instructionsПостійні правила для проєкту в .md-файлах (стиль коду, команди збірки).
SkillПапка з SKILL.md і ресурсами — «навичка», яку агент підвантажує, коли задача підходить за описом.
Prompt fileЗбережений багаторазовий промпт (*.prompt.md), що викликається командою /назва.
Custom agent / chat modeПерсона з власними інструкціями й набором дозволених інструментів (рев'юер, архітектор).
Субагент (subagent)Допоміжний агент, якому основний делегує підзадачу в окремому контексті.
HooksСкрипти, що спрацьовують у певні моменти (перед запуском інструмента, після редагування) — для контролю й автоматизації.
Human-in-the-loopЛюдина підтверджує небезпечні дії (запуск команд, запис файлів).
Autopilot / auto-approveАгент виконує дії без запитів. Швидко, але ризиковано.
Premium request / квотаОблікова одиниця у Copilot: складні моделі й агентні режими споживають більше.
Практичний висновок: якість відповіді = якість моделі × якість контексту × якість інструкцій. Далі в підручнику ми вчимося керувати двома останніми множниками.
Завдання 2. Без підглядання поясніть своїми словами: чим відрізняється токен від слова; чому довга розмова може «забути» початок; чим skill відрізняється від MCP-сервера (підказка: skill — знання/інструкція, MCP — доступ до зовнішніх дій і даних).

3.2. Що обрати .NET-розробнику-новачку

  • Основний інструмент: GitHub Copilot — глибока інтеграція з Visual Studio і VS Code, підтримка кількох моделей, агентний режим, MCP, інструкції та skills.
  • Для навчання й консультацій: один веб-чат (ChatGPT / Claude / Gemini) на ваш смак.
  • Пізніше: Copilot CLI та cloud agent для автоматизації.

3.3. Різні моделі — різні сильні сторони

Клас моделіХарактеристикаВикористання
Швидкі / «mini», «flash», «haiku»Дешеві, швидкі, простішіАвтодоповнення, дрібні правки, пояснення
Універсальні «стандартні»Баланс ціни й якостіОсновна робота, агентні задачі
Reasoning / «max»Повільні, дорогі, глибше міркуютьСкладні баги, архітектура, великі рефакторинги

Правило: починайте зі стандартної моделі, ускладнюйте лише коли вона не справляється. У Copilot модель обирається у випадаючому списку чату; режим Auto підбирає її за вас.

3.4. Ваш перший робочий цикл у Copilot

  1. Встановіть Visual Studio 2022+ (або VS Code з C# Dev Kit) і увійдіть під GitHub-акаунтом із Copilot.
  2. Відкрийте TodoApi. Відкрийте вікно Copilot Chat.
  3. Виділіть код у Program.cs і спитайте: «Explain».
  4. Попросіть: «Додай модель TodoItem (Id, Title, IsDone) та мінімальні ендпоінти CRUD у пам'яті».
  5. Перевірте: dotnet build, запустіть, випробуйте через Swagger/.http-файл.

3.5. Безпека з першого дня

  • Не вставляйте в чат паролі, ключі API, рядки підключення, персональні дані.
  • Секрети тримайте в User Secrets / Key Vault, не в коді — AI має це знати (пропишемо в інструкціях, розділ 7).
  • Перевіряйте, чи дозволяє ваш роботодавець використання AI з кодом проєкту.
  • Перевіряйте залежності, які пропонує AI: пакет має існувати у NuGet і бути надійним.
